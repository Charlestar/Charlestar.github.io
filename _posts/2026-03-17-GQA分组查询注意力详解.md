## 1. MHA、MQA 与 GQA

设 query heads 为 $H_q$，KV heads 为 $H_{kv}$：

- MHA：$H_{kv}=H_q$；
- MQA：$H_{kv}=1$；
- GQA：$1<H_{kv}<H_q$，每组 query heads 共享一对 K/V heads。

实现通常要求 $H_q$ 能被 $H_{kv}$ 整除。计算时可以逻辑广播 K/V，不一定需要在显存中真的复制。

## 2. KV Cache 收益

忽略元数据时，每 token 的 KV Cache 与 $H_{kv}$ 成正比：

$$M_{token}=2LH_{kv}DB$$

因此从 32 个 KV heads 改为 8 个时，这一部分理论上降为原来的 25%；实际总显存还包含权重、激活、allocator 对齐和其他缓存，不能写成“总显存降低 75%”。

## 3. 质量与 uptraining

GQA 论文研究了把已有 MHA checkpoint 转成较少 KV heads，再用一小部分预训练计算继续训练。论文中的 5% 是特定实验设置，不是所有模型转换都只需固定 5%，更不能推出质量差距恒小于 1%。

直接平均 K/V heads 只是初始化策略；若不继续训练，质量可能明显下降。最佳分组数还取决于模型规模、训练数据和 serving 约束。

## 4. 实现检查

- 明确 checkpoint 的 `num_attention_heads` 与 `num_key_value_heads`；
- 确认 RoPE、tensor parallel 切分和 attention backend 支持该分组；
- 不在热路径物理 `repeat` 整个 KV Cache；
- 用目标任务验证质量，并分别测 prefill、decode 与峰值缓存。

## 5. 张量形状与分组映射

常见布局中：

```text
Q: [batch, seq, H_q, d]
K: [batch, seq, H_kv, d]
V: [batch, seq, H_kv, d]
group_size = H_q / H_kv
kv_head(query_head h) = floor(h / group_size)
```

例如 $H_q=32,H_{kv}=8$ 时，每 4 个 query heads 共享一个 KV head。kernel 可以根据映射读取对应 KV，不必执行 `repeat_interleave` 生成 32 份物理 K/V。

## 6. 缓存估算示例

假设 32 层、head dimension 128、BF16、上下文 4096，单条序列的 KV Cache 近似为：

$$2\times32\times4096\times H_{kv}\times128\times2\ \text{bytes}$$

- $H_{kv}=32$：约 2 GiB；
- $H_{kv}=8$：约 0.5 GiB；
- $H_{kv}=1$：约 64 MiB。

这只是 KV tensor 本体，用于理解比例；真实分配还受 batch、块对齐、并行切分和 allocator 影响。

## 7. 从 MHA checkpoint 转换

一种初始化方法是在每组内平均原有 K/V projection heads，再继续训练：

```text
Wk_group[g] = mean(Wk[h] for h in group g)
Wv_group[g] = mean(Wv[h] for h in group g)
```

继续训练让模型适应共享表示。分组方式不一定只能连续分组，质量也不只由 KV head 数决定；训练预算、数据混合和学习率同样重要。

## 8. 与 Tensor Parallel 的交互

当 $H_{kv}$ 小于 TP rank 数时，某些 rank 无法各自获得独立 KV head，框架可能复制 KV heads 或采用特殊切分。选 TP 大小时应检查实现约束，否则理论缓存节省可能被跨 rank 复制部分抵消。
