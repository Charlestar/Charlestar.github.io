## 1. 先定义 workload

引擎不存在脱离 workload 的统一排名。至少要固定模型/量化、GPU 与互联、输入/输出长度分布、并发、采样方式、SLO 和是否存在共享前缀，再比较 TTFT、TPOT、吞吐、goodput、显存和运维复杂度。

## 2. 三类引擎的侧重点

| 引擎 | 主要优势 | 需要重点评估 |
|---|---|---|
| vLLM | 模型生态广、OpenAI-compatible serving、PagedAttention/continuous batching、分布式与插件能力 | 新功能组合的支持矩阵、版本迁移、backend 选择 |
| SGLang | RadixAttention 前缀复用、结构化生成、面向 agent/RAG 的运行时优化 | 前缀命中分布、模型支持、server/DSL API 的版本变化 |
| TensorRT-LLM | NVIDIA 平台上的编译优化、量化与多 GPU kernel/通信集成 | 构建与部署复杂度、engine 兼容性、NVIDIA 硬件绑定 |

“通用”“Agent 原生”或“性能极致”都只是方向，不是保证。vLLM 也支持 prefix caching 和 structured output，SGLang 也能服务普通 API，TensorRT-LLM 也在改进动态图与易用性。

## 3. 推荐的基准方法

1. 使用同一 checkpoint、dtype/量化、并行度与 sampling 参数。
2. 预热后分别测离线吞吐和在线请求率扫描。
3. 报告 P50/P95/P99 TTFT、TPOT 和端到端延迟。
4. 记录失败率、OOM、抢占、prefix cache hit 与实际 backend。
5. 做成本比较时包含编译、冷启动、运维与资源碎片，而非只除以峰值 tok/s。

## 4. 选型建议

- 优先模型覆盖和快速上线：先验证 vLLM。
- 大量共享 system prompt、树状探索或结构化生成：重点比较 SGLang。
- NVIDIA 固定模型、量化与长期稳定高负载：把 TensorRT-LLM 纳入测试。
- 多种 workload 并存：允许按模型池选择不同引擎，比追求单一标准更现实。

## 5. 请求生命周期对比

三者都大致经历 tokenizer、排队、调度、模型执行、采样和流式返回，但优化位置不同：

```text
HTTP request
 -> tokenizer / input validation
 -> request queue
 -> scheduler + KV cache manager
 -> model runner + attention/GEMM kernels
 -> sampler
 -> streaming response
```

vLLM/SGLang 偏向动态 serving runtime，运行时根据请求组合 batch；TensorRT-LLM 更强调针对模型和 NVIDIA 平台构建高度优化的执行路径。比较时要确认 tokenizer、HTTP frontend 和 streaming 是否计入，否则“引擎吞吐”与用户观测延迟会错位。

## 6. 并行与缓存维度

- Tensor Parallel 切单层计算，通信频繁但单模型易扩展。
- Pipeline Parallel 切层，可能产生 pipeline bubble。
- Data Parallel 复制模型，适合扩吞吐并可结合请求路由。
- Expert Parallel 专用于 MoE 专家切分。
- Prefix cache、KV offload 和 Prefill/Decode disaggregation 会进一步改变容量与路由策略。

引擎“支持某种并行”不等于任意组合都成熟。测试矩阵应覆盖实际准备上线的模型、量化、并行与 backend 组合。

## 7. 一份可执行的 benchmark 记录

```yaml
model: exact checkpoint revision
engine: name + version + commit
hardware: GPU model/count/interconnect
precision: weight/activation/KV dtype
parallelism: TP/PP/DP/EP
traffic: request rate + concurrency
input_tokens: distribution, not only average
output_tokens: distribution, not only max
metrics: TTFT/TPOT/E2E P50/P95/P99, throughput, failures
```

缺少这些字段的数字适合做线索，不适合做采购或架构结论。
